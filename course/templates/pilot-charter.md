# Pilot charter: completed fictional example

- **Owner:** Maya, Harbour operations lead.
- **Process:** weekly operations-draft preparation, using authorised fictional records.
- **Participants:** one preparer and one reviewer; no customer-facing deployment.
- **Window:** one classroom reporting cycle, with the exact start/end recorded by the learner.
- **Success:** correct reconciliation and source-backed policy; all unresolved data visible; review effort measured; no external business actions.
- **Inputs:** the approved course pack and separately versioned learner changes.
- **Review duty:** Maya reviews every report. Leo handles service exceptions. Unassigned data investigations remain in the queue until assigned.
- **Budget:** set and record an account-specific limit before using any paid service; disable or pause runs at the limit.
- **Stop conditions:** unauthorised action, access failure, unexplained data disclosure, exhausted budget, or no available reviewer.
- **Fallback:** prepare the report manually using the same source contract and calculation reference.
- **Feedback:** record each correction, unclear interface, missing source, and staff intervention with its case ID.
- **Decision meeting:** compare baseline and pilot evidence, then choose adopt, revise, or stop for a precisely defined scope.

For a real pilot, replace the fictional names and records, confirm organisational authorisation, define actual dates and thresholds, and get the named owners' agreement.
