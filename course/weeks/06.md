# Week 6: Private knowledge and retrieval

A knowledge assistant needs the right evidence, not just a fluent answer. This week separates document selection, search, and answer generation so that each can be tested. Use the dated and permission-labelled Harbour policy passages.

## 1. Build a retrieval pipeline with explicit boundaries

Retrieval-augmented generation supplies selected source passages to a model at answer time. The pipeline has several decisions: which documents exist, who can access them, which versions apply, how passages are represented, which ones are selected, and what the answer is allowed to claim.

Start with a simple keyword baseline. It is cheap, inspectable, and often strong when users ask about exact product names or policy terms. Embeddings represent content as vectors so search can find related language even without the same words. Similarity is a retrieval signal, not a probability that a passage is correct. Hybrid search combines approaches; introduce it only if it addresses observed misses.

A chunk needs enough context to preserve the rule. Splitting "above AUD 250" away from "also needs the operations lead" makes both fragments less useful. Attach document ID, version, effective dates, status, and access labels to every derived passage. Index updates and deletions must propagate to those derivatives.

Filter permissions before presenting candidates to the generator. Hiding a citation after the model has read a private passage does not undo the disclosure. In this lab the application supplies the role. Allowing the model to request the manager role would turn access control into a suggestion.

The [retrieval paper by Lewis and colleagues](https://arxiv.org/abs/2005.11401) is foundational research on combining retrieval with generation. The metadata, access checks, and effective-date rules here are additional application responsibilities, not automatic properties of RAG.

## 2. Evaluate retrieval and answers separately

For a question with a known supporting passage, first ask whether search retrieved it. If not, improving the answer prompt cannot repair the absent evidence. Then ask whether the generated answer accurately uses the retrieved passage and avoids unsupported additions.

For a small classroom set, record expected supporting IDs, returned IDs, answer correctness, citation support, and whether abstention was appropriate. Recall at k measures how much relevant evidence appears among the first k results under your labelling scheme. More retrieved text is not always better: it can add irrelevant material, conflicting versions, and cost.

### Worked case

Question: "As of 8 October, may the assistant approve a refund of AUD 200?" The answer is no. P01-v2 requires service-manager approval for every refund. The additional operations-lead threshold applies above AUD 250. Retrieving P01-draft because it contains "assistant approve" would supply a tempting but unauthorised answer.

Question: "What was the additional approval threshold on 3 October?" The historical answer uses P01-v1 and AUD 500. A rule that simply deletes every retired document would prevent this historical query. Retention and access policies determine whether historical material should be available; effective dating determines whether it is applicable.

Question: "What supplier fee target should an analyst report?" The analyst has no authorised supporting source. The correct result is insufficient authorised evidence. The system should not reveal the existence or content of a restricted negotiation document in its explanation.

## 3. Studio, freshness tests, and evidence

### Engineering route

1. Run `node course/labs/reference.mjs retrieve "refund approval" analyst` and inspect the returned IDs.
2. Read the filtering code. Test an invalid role and verify that it is rejected.
3. Create twenty questions: twelve answerable, three missing evidence, three version-sensitive, and two permission-sensitive.
4. Measure keyword retrieval before adding embeddings or a reranker. Use the same questions after any change.
5. Pass only authorised passages to a model and require passage IDs beside factual claims.
6. In a copy of the corpus, change a policy and remove a document. Rebuild or update the index and verify the old active passage no longer appears for current queries.

### Business-owner route

1. Identify who owns each source and when it becomes effective. Mark approved, draft, retired, and restricted material.
2. Configure an approved knowledge tool with a small collection, or use the instructor's prepared environment.
3. Write twenty questions with expected supporting documents before inspecting generated answers.
4. Test the same update, removal, and access cases as the engineering route. Capture evidence of the actual configuration, not just a privacy promise in a prompt.
5. Write the maintenance procedure: who corrects a source, how quickly a correction reaches answers, and how staff report unsupported claims.

### Answer review

An answer can be factually correct by chance and still fail grounding if its citation points to a draft. An answer can cite a relevant source yet miss a qualification. Grade support at the claim level, particularly for amounts, dates, and permissions.

Submit the question set, stage-level results, a sample cited answer, an appropriate abstention, and evidence of update/removal propagation. Do not pass this week's lab if a private passage enters the prompt for an unauthorised user.
