### Engineering route

1. Run `node course/labs/reference.mjs retrieve "refund approval" analyst` and inspect the returned IDs.
2. Read the filtering code. Test an invalid role and verify that it is rejected.
3. Create twenty questions: twelve answerable, three missing evidence, three version-sensitive, and two permission-sensitive.
4. Measure keyword retrieval before adding embeddings or a reranker. Use the same questions after any change.
5. Pass only authorised passages to a model and require passage IDs beside factual claims.
6. In a copy of the corpus, change a policy and remove a document. Rebuild or update the index and verify the old active passage no longer appears for current queries.

### Business-owner route

1. Identify who owns each source and when it becomes effective. Mark approved, draft, retired, and restricted material.
2. Configure an approved knowledge tool with a small collection, or use the instructor's prepared environment.
3. Write twenty questions with expected supporting documents before inspecting generated answers.
4. Test the same update, removal, and access cases as the engineering route. Capture evidence of the actual configuration, not just a privacy promise in a prompt.
5. Write the maintenance procedure: who corrects a source, how quickly a correction reaches answers, and how staff report unsupported claims.

### Answer review

An answer can be factually correct by chance and still fail grounding if its citation points to a draft. An answer can cite a relevant source yet miss a qualification. Grade support at the claim level, particularly for amounts, dates, and permissions.
