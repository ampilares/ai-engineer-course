A model that answers in prose is a demo. A model that reliably fills a **schema** is a component you can build systems on. Structured output is the bridge between probabilistic text and deterministic software: arguably the single most-used primitive in applied AI engineering.

## The contract: define, demand, validate

```python
from pydantic import BaseModel, field_validator

class InvoiceExtract(BaseModel):
    vendor: str
    invoice_number: str
    total_cents: int
    currency: str            # ISO 4217
    due_date: str | None     # YYYY-MM-DD; null if absent

    @field_validator("currency")
    @classmethod
    def iso_currency(cls, v: str) -> str:
        if len(v) != 3 or not v.isalpha():
            raise ValueError("must be a 3-letter ISO code")
        return v.upper()
```

Use four layers. First, define the schema in code and provide it to the model through the provider's structured-output or tool-schema mode when available. Second, validate every response with the same schema object because syntactic constraints do not guarantee correct values. Third, on a repairable failure, retry once with a concise validation error such as "`total_cents` must be an integer; return corrected JSON only." Fourth, route repeated failures to a human or a safe terminal state. Never let unvalidated model output reach downstream systems.

## Schema design moves the quality needle

The schema isn't just plumbing: it shapes model behavior:

- **Field names and descriptions are prompt text.** `total_cents: int: grand total including tax, in cents` outperforms `amt: int`.
- **Enums beat free strings.** `category: "billing" | "technical" | "other"` eliminates a whole class of creative misspellings.
- **Make uncertainty representable.** A nullable field plus a `confidence: float` per critical field gives the model a legal way to say "not stated": otherwise it will *invent* a due date rather than omit one. You are designing the model's abstention path.
- **Order matters.** Since generation is sequential (Module 7), putting a `summary` or `reasoning` field *before* the extracted fields lets the model "think" before committing values: schema-shaped chain of thought.

## Confidence routing: the pattern behind every AI product

With validated, confidence-annotated output you can build the workhorse architecture of applied AI:

```text
model output → validate → confidence ≥ threshold? → auto-process
                        → confidence < threshold  → human review queue
                        → invalid after retry     → human review queue
```

Confidence routing can make a model useful even when its raw accuracy is insufficient for full automation. Automatically process only outputs that pass schema, business-rule, and confidence checks, then route ambiguous or invalid cases to a human. End-to-end quality depends on how well the threshold separates cases and how reliable the review process is; it is not guaranteed by the pattern. The threshold is a business decision informed by Module 5's precision and recall trade-off. Reviewed corrections can become evaluation data in Module 14 and, after curation, training data in Module 17.

## Syntactic validity is only the first gate

Schema-valid output can still be wrong. Add semantic checks: totals equal line items, dates fall in an allowed range, identifiers exist, currency belongs to an enum, and mutually exclusive fields do not appear together. Use discriminated unions for genuinely different outcomes such as `approved`, `needs_review`, and `rejected`; one giant object full of optional fields permits impossible combinations.

Distinguish “unknown” from an empty string, zero, or false. Require evidence spans or source references for fields that matter. Confidence emitted by the same model is not calibrated probability. Route using observable signals such as missing evidence, validation failures, disagreement between passes, or measured performance for that document type.

On failure, prefer a bounded repair step that receives validation errors and the original output. Never retry indefinitely, and never let a repaired structure erase the raw attempt. Some inputs should go directly to review rather than paying for repeated guesses.
