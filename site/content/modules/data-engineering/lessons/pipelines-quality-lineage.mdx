A pipeline is reliable when the same declared inputs and code produce a known output, failures are visible, and recovery does not require guessing. Scheduling tasks is the easy part; maintaining trustworthy state is the work.

## Build idempotent stages

Divide the path into stages with explicit input and output contracts: discover, extract, validate, normalize, enrich, publish. Give each run and record stable identifiers. A stage should either replace a versioned partition atomically or upsert by a deterministic key. Writing random duplicate rows on every retry is not orchestration.

Checkpoint after durable output, not merely after a function returns. Use bounded retries for transient failures and quarantine deterministic data failures. Backfills are normal operations: they need parameters, resource limits, isolated outputs, and promotion checks so historical recomputation does not overwhelm current production work.

## Quality gates at the boundary

Test data like an interface. Useful checks include:

- schema and type compatibility;
- required-field and uniqueness constraints;
- accepted value ranges and referential integrity;
- volume, freshness, and duplicate-rate expectations;
- distribution changes by important segment;
- reconciliation against source totals.

Not every anomaly should stop the pipeline. Classify checks as fail, quarantine, warn, or observe, and assign an owner. A freshness warning without an owner is only a dashboard decoration. Compare against recent seasonal baselines rather than a fixed threshold when normal volume changes by weekday.

## Lineage makes change reviewable

Lineage links an output field or dataset to source versions, transformations, code/config, and run. At minimum, store dataset version, pipeline commit, run ID, source delivery IDs, timestamps, and quality results. For model artifacts, link training and eval data versions to the resulting model. For RAG, link index versions to parser, chunker, embedding model, and source snapshot.

Use lineage for blast-radius analysis. When a currency conversion bug is found, ask which datasets, models, eval reports, and decisions consumed the affected version. Without lineage, teams either underreact or rebuild everything.
