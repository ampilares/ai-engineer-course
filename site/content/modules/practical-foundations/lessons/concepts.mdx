This week you will choose one task, describe acceptable work, and record a baseline. Engineers should budget 8-10 hours; business owners 5-7 hours. Begin with the [Harbour Services case](/course-materials/course/case-study/README.md), then repeat the exercise on an authorised process you know.

An AI model transforms inputs into outputs using patterns learned during training. Inference is using that trained model on a new input. A conversation does not ordinarily retrain the underlying model. A product may save preferences, retrieve documents, or provide tools around it; those are additional parts of the system.

An assistant is the interface through which you ask for work. A workflow follows a defined sequence, such as reading a request, checking required fields, classifying it, and placing a draft in a review queue. An agent selects its next action from available tools based on what it observes. A language model can participate in either a workflow or an agent. Calling every automated process an agent obscures who controls the next step.

Deciding who may issue a refund is an authority question. Give calculation to code, use a model to suggest a classification, and enforce refund authority in application permissions. Asking a more capable model to do all three does not remove the need for these distinctions.

Language models process tokens, which are pieces of text rather than necessarily complete words. A context window limits what the model can use during one request. Long conversations and attachments consume that capacity; a product may retrieve or summarise some material rather than include it all. A convincing answer is not evidence that every source was read. Ask for a specific source ID and verify the relevant passage yourself.

The workflow/agent distinction is supported by [Anthropic's engineering guidance](https://www.anthropic.com/engineering/building-effective-agents). Our placement of arithmetic, classification, and authorisation is a design for this course's fictional business, to be tested against its requirements.

### A useful decision procedure

Start with the required output and the consequence of getting it wrong. If a formula or lookup fully specifies the answer, use that first. If the task predicts a numerical outcome from labelled historical data, investigate a predictive model and a simple baseline. If language interpretation is needed, try one bounded model call. Introduce an agent only when selecting the next tool is itself useful. Compare the additional setup and review work with the simpler process.
