### Engineering route

1. Complete the vertical slice and test it on three development cases: normal, ambiguous, and unavailable dependency.
2. Run automated interface, business-rule, permission, and recovery checks appropriate to your architecture.
3. Package the setup, fixture inputs, and operational commands so another engineer can reproduce the run.
4. Review the diff for broad permissions, unnecessary dependencies, and unrelated changes.
5. Record remaining limitations and choose what is required before the pilot can start.

### Business-owner route

1. Complete the configured workflow or assistant and test the staff-facing process from intake to review.
2. Verify the reviewer can see evidence, correct a result, reject an action, and locate unresolved work.
3. Ask a second person to follow the operating procedure with a new case.
4. Check the cost and support assumptions with the implementation owner.
5. Sign off the bounded pilot scope, or narrow it until the acceptance criteria are achievable.
