## Values and names

Python programs manipulate **values**: numbers, text, true/false flags. You give values names with `=`:

```python
price = 4180          # an integer
vendor = "Nordwind"   # a string (text in quotes)
paid = False          # a boolean: True or False
rate = 0.19           # a float (decimal number)
```

A name is a label stuck on a value: `price` now *means* 4180 wherever you use it. Everything after `#` is a **comment**: notes for humans, ignored by Python.

You combine values with operators, and `print()` shows results:

```python
total = price * (1 + rate)
print(f"Total incl. tax: {total}")   # f-string: puts values inside text
```

That `f"...{total}"` is an **f-string**: the `{}` slots get filled with the value. You'll use it constantly.

## Decisions: if, elif, else

Programs choose between paths with conditions:

```python
if total > 10000:
    review = "manager approval required"
elif total > 1000:
    review = "standard review"
else:
    review = "auto-approve"
```

Two things matter here. Comparisons (`>`, `<`, `==` for equals, `!=` for not-equals) produce `True` or `False`. And **indentation is the structure**: the indented lines belong to their condition. Python has no braces; the spaces *are* the syntax: four spaces per level, and consistency is mandatory.

## Strings: the data type AI runs on

Language models eat and produce text, so strings get special attention all course long:

```python
name = "  Ada Lovelace \n"
clean = name.strip()          # "Ada Lovelace": whitespace removed
loud = clean.upper()          # "ADA LOVELACE"
parts = clean.split(" ")      # ["Ada", "Lovelace"]: a list (next lessons)
"Ada" in clean                # True: substring check
```

Those `.strip()`, `.upper()` are **methods**: capabilities attached to a value, called with a dot. Different types have different methods; text manipulation like this is the daily bread of data cleaning and prompt building.
