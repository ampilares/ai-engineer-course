A program of any size is built from **functions**: named, reusable blocks that take inputs and return outputs. Functions are also where this course's engineering standards begin: typed signatures, one job per function, and honest error handling.

## Defining and calling

```python
def net_to_gross(net: float, rate: float = 0.19) -> float:
    """Add tax to a net amount."""
    return net * (1 + rate)

price = net_to_gross(100.0)        # 119.0: rate used its default
special = net_to_gross(100.0, 0.07)  # 107.0
```

Read the pieces: `def` starts a definition; parameters in parentheses are the inputs; `-> float` announces what comes back; the indented body runs when *called*, not when defined; `return` hands the result to the caller. The `"""docstring"""` describes the function for humans (and, later, for AI tools reading your code).

The type hints (`net: float`) don't change how the code runs (Python stays dynamic) but they document intent, let tools catch mistakes before runtime, and are non-negotiable style in this course.

## When things go wrong: exceptions

Code fails: files are missing, text isn't a number, networks drop. Python signals failure by **raising an exception**, which crashes the program *unless you catch it*:

```python
def parse_amount(text: str) -> float | None:
    """Turn '4,180.00' into a number; None if it isn't one."""
    try:
        return float(text.replace(",", ""))
    except ValueError:
        return None
```

The pattern: `try` the risky thing; `except SpecificError` handles that failure. Two professional habits, both previewing Module 3:

- **Catch the specific exception**, not everything. A bare `except:` silences bugs you needed to see.
- **Turn failures into data** where callers can act on it: here, `None` means "not a number", and the `float | None` hint tells everyone to expect that.
