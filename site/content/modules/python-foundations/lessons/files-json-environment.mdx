Programs that only compute in memory are toys. Real work reads data in, writes results out, and runs in an environment you control. This lesson moves you from browser exercises to running Python **on your own machine**, which the rest of the course requires.

## Files: reading and writing

```python
# Write text to a file ('w' = write, overwrites; 'a' = append)
with open("report.txt", "w", encoding="utf-8") as f:
    f.write("42 invoices processed\n")

# Read it back
with open("report.txt", encoding="utf-8") as f:
    content = f.read()
```

The `with` block guarantees the file closes even if an error occurs inside: the same "clean up no matter what" discipline you met with exceptions. And `encoding="utf-8"` prevents an entire category of mangled-character bugs; make it a reflex.

## JSON: how systems talk

**JSON** is the text format APIs, config files, and model outputs use, and it maps directly onto the Python you just learned: JSON objects ↔ dicts, arrays ↔ lists.

```python
import json

invoice = {"vendor": "Nordwind", "total": 4180, "items": ["freight", "fuel"]}

text = json.dumps(invoice, indent=2)   # dict → JSON string
restored = json.loads(text)             # JSON string → dict
restored["total"]                       # 4180
```

`dumps`/`loads` (and their file cousins `dump`/`load`) are the bridge you'll cross in every module: API responses in, model outputs parsed, eval datasets saved. One warning that will echo in Module 8: **text claiming to be JSON isn't always valid JSON**: `json.loads` raises on malformed input, so it belongs inside a `try/except` when the text comes from anywhere you don't control (including a model).

## Your machine: Python, venv, and packages

Install [Python 3.12+](https://www.python.org/downloads/) and run these in a terminal:

```bash
mkdir ai-course && cd ai-course
python -m venv .venv                 # create an isolated environment
# activate it:
#   Windows:  .venv\Scripts\activate
#   macOS/Linux:  source .venv/bin/activate
pip install httpx pytest             # install packages INTO this project
python -c "print('hello from my machine')"
```

A **virtual environment** gives each project its own package versions. Without isolation, upgrading a library for one project can silently break another. Use one virtual environment per project and record dependencies in a lock file or requirements file so another person, including your future self, can rebuild the environment. For this course, `pip freeze > requirements.txt` is an acceptable starting point.

`import` is how code uses packages and the standard library: you've seen `import json`; Module 3 will add `httpx` for APIs and `sqlite3` for databases. A **script** is just a `.py` file run with `python name.py`, from here on, labs happen there.
