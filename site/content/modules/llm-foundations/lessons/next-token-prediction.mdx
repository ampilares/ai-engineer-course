Strip away the chat interface, the personality, the apparent reasoning, and a large language model does exactly one thing: given a sequence of tokens, it outputs a **probability for every possible next token**. That's the entire machine. Everything else is this operation repeated.

## The loop that writes everything

When a model "writes an essay," this happens:

1. Your prompt is converted into tokens (next lesson).
2. The model computes a probability distribution over its whole vocabulary (~100k tokens) for what comes next.
3. One token is **sampled** from that distribution.
4. The chosen token is appended to the sequence, and the process repeats: one token at a time, each conditioned on everything so far.

A decoder still emits the response one token at a time. It does not maintain a guaranteed symbolic outline that the application can inspect. Plans may be represented implicitly in internal activations or explicitly in generated context, and reasoning models may spend additional tokens constructing them. The final structure still emerges through sequential generation conditioned on the prompt and all tokens produced so far.

## Why a simple objective produces capable behavior

Predicting the next token *well* is secretly hard. To predict the next word of:

- *"The capital of Australia is"*: you need geography.
- `def fibonacci(n): if n <= 1: return`: you need to execute code in your head.
- *"She put the ice cream in the oven. An hour later it was"*: you need physics and time.
- *"I asked for a refund and they said no, so I feel"*: you need a theory of human emotion.

Train a large enough model on a large enough slice of human text, and getting the next token right **forces** it to internalize compressed approximations of all of this. Capability is a side effect of compression. This is the deepest idea in the module: nobody taught the model grammar, facts, or logic: they precipitated out of the prediction task.

## What this single fact already predicts

Before you learn any internals, next-token prediction alone explains behaviors you'll manage for the rest of the course:

- **Fluency ≠ truth.** The model produces *plausible* continuations. Plausible and true usually coincide on well-represented facts, and diverge on rare ones. That divergence has a name: hallucination (final lesson).
- **Wording moves behavior.** The prompt is the conditioning context; change it and every downstream probability shifts. That's why "prompt engineering" isn't superstition (Module 8).
- **It can't know when it doesn't know**: the machine always produces a distribution; there's no built-in "empty result." Abstention has to be engineered around the model.

## From text to a learning signal

Training text is shifted by one position: the tokens at positions 1 through *n−1* are inputs, and positions 2 through *n* are targets. One sequence therefore supplies many supervised examples at once. At every position the model produces a **logit** for every vocabulary token; softmax turns those scores into a probability distribution, and cross-entropy penalizes the probability assigned to the observed next token. Backpropagation then adjusts billions of shared parameters.

The same model can summarize, translate, classify, and write code because each task can be represented as text followed by an appropriate continuation. Post-training makes useful continuations easier to elicit, but generation still remains repeated probability estimation. This explains two engineering facts: a fluent answer is not proof of truth, and small changes in context can change every later probability.

Teacher-forced training sees the correct previous token, while inference sees the model’s own sampled tokens. An early mistake can therefore move generation into a different region of probability space. Evaluation must cover complete outputs, not only the first token.
