# Week 10: Repeatable procedures with Hermes Agent

This week you will turn a successful procedure into a reviewed skill and test it after the conversation context has changed. Improvement means better measured outcomes or less intervention on new cases, not merely a saved file or a confident promise.

## 1. Configure the agent and distinguish its stores

Hermes Agent is the Nous Research application used in this module. It can use different model providers. Its name should not be confused with the Hermes model family. Follow the [official quickstart](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart) to install in a dedicated environment and configure an approved provider.

```bash
hermes setup
hermes model
```

Use setup to choose the necessary capabilities, then verify one normal conversation. Configure isolation and tool access before supplying untrusted files. The [security guide](https://hermes-agent.nousresearch.com/docs/user-guide/security) describes approval and execution-environment controls. A minimal set of enabled tools can still include a powerful terminal; minimal does not automatically mean confined.

Memory stores selected information across sessions. Skills describe procedures and may include supporting files. The live conversation contains temporary task context. The [memory documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory) explains that persistence requires an actual write; an assistant saying it remembered something is not evidence of a saved entry. Confirm the stored artifact or recorded write, then test in a fresh session.

Pick a stable preference for the exercise: reports use a fixed section order and show unresolved questions explicitly. Do not use a changing refund threshold as a permanent fact. Ask the agent to retrieve the effective policy when that threshold matters.

## 2. Teach a skill and test transfer

Run the Harbour weekly report once with a clear brief. Review the result. Correct a real error, such as including S009 outside the period or assuming S010's missing amount is zero. Only after a successful run should you capture the procedure.

The [skills documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills) describes reusable skill files and supporting resources. Use the original [Harbour report skill](../templates/harbour-report-skill.md) as a starting specification. Inspect any generated procedure before enabling it. Check that it refers to the input contract and verification steps rather than embedding last week's output.

### A procedure worth saving

The skill should validate the reporting period, inspect the data contract, calculate accepted totals, retrieve current authorised policy, produce a draft, and stop for review. It should not memorise "the answer is 6,300." Its output requirements should include missing data and exceptions. Its permissions should be narrower than a general-purpose computer operator's when possible.

Now change the task. In a copied CSV, correct S010 to a known AUD amount, or change the reporting period. Start a new session and rerun the procedure. A reusable procedure updates the result from the sources. If it repeats the previous amount, investigate whether stale context, a cached artifact, or the skill itself supplied the answer.

### Evaluate a claimed improvement

Run at least five cases before and after the skill change. Measure task correctness, source reopening, review time, and human corrections. A reduction from three reminders to one is useful evidence on that sample, but it does not establish that the agent will improve indefinitely. Keep the old skill version so you can compare or restore it.

## 3. Studio, memory correction, and evidence

### Engineering route

1. Set up a dedicated Hermes environment with the required model and only the tools needed for the report.
2. Verify one report against the independent reference calculation.
3. Create or adapt the report skill, inspect supporting scripts, and save a versioned copy without credentials.
4. Ask the agent to remember the report format. Verify that the memory was written, then begin a fresh session using the documented session control for your interface.
5. Introduce a stale preference or policy assumption, correct or remove it, and verify the correction in another fresh session.
6. Compare five cases with and without the revised skill. Record visible model and configuration differences.

### Business-owner route

1. Use the prepared environment to demonstrate the report procedure in plain language.
2. Review the saved procedure as you would a staff operating procedure: are inputs, checks, exceptions, and responsibilities explicit?
3. Ask for a new reporting period and a changed dataset. Check that the output changes for the right reason.
4. Correct a mistaken preference and verify the next session uses the correction.
5. Decide who may approve changes to the skill and how users can return to a known-good procedure.

### Worked interpretation

Saving a preferred heading order is a memory action. Editing the report workflow is a skill change. Updating a refund rule belongs in the authoritative policy. None of these, by itself, changes the model's learned weights. Persistent memory also creates retention obligations: remove material that the agent no longer needs and check other copies such as logs and exported files.

Submit the skill, its change history, persistence evidence, five-case comparison, and a correction demonstration. If you only used an instructor replay, identify which actions you observed and which you did not perform. The course provides procedures and fixtures; it does not assert that a live Hermes instance has been tested on your account.
