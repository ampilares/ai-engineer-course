# Week 3: Data, documents, and media

This week produces an analysis that another person can reproduce. Keep the raw source, transformation rules, calculated results, and interpretation distinguishable. The same discipline applies whether the assistant reads a CSV, screenshot, PDF, or recording.

## 1. Establish a data contract before analysis

Read [the Harbour data contract](../case-study/README.md) before touching the CSV. A transaction ID identifies a business event. One duplicate row does not represent additional income. A missing amount is unknown; replacing it with zero conceals a data problem. USD and AUD cannot be summed as though they were the same unit.

Use four stages: preserve, validate, transform, and reconcile. Preserve the original file. Validate columns, date formats, identifiers, currency, and amount representation. Transform only records that meet the stated rules. Reconcile counts so that every input row has an explanation.

For Harbour, 12 rows become 11 unique IDs after removing one exact duplicate copy. One ID falls outside the period. Two IDs require review. Eight events remain for the accepted AUD calculation. An analysis that reports eight events but cannot account for the other four rows is incomplete.

Use integer cents or an appropriate decimal type for money. Binary floating-point calculations can introduce representation errors. The fixture reference tool converts two-decimal amounts to cents before addition. In a spreadsheet, make currency and inclusion criteria explicit, preserve raw rows, and use formulas on the prepared data rather than typing the final total.

The [Python CSV reference](https://docs.python.org/3/library/csv.html) documents practical details such as quoted fields and newline handling. The supplied JavaScript teaching reader deliberately accepts only this fixture's simple unquoted format and rejects unexpected formats. A production import should use a suitable parser and a tested source contract.

## 2. Preserve evidence across document and media tasks

Extraction is observing fields; calculation is deriving a value. In [INV-014](../case-study/document.txt), line items sum to AUD 220, while the printed total contains an unreadable character. Store the observed total as unknown, the calculated subtotal as 220.00, and a review reason. Filling the unreadable character with zero would merge inference with observation.

Keep document ID, page or region, extracted text, normalised value, and validation result. A clean JSON object can still contain a wrong date or a fabricated amount. Check fields against the source and enforce business rules after extraction. Unknown values should survive until a person or an authoritative source resolves them.

For meeting work, preserve timestamps, speakers, and corrections. The Harbour transcript first mentions 5 October and then corrects the date to 6 October. The final action list should reflect the correction and cite the policy it refers to. The missing-amount investigation has no assigned owner. Write "owner unresolved" instead of inventing one.

For images and charts, inspect labels, units, scale, and the underlying data if available. A rising line does not establish a percentage increase without values. For audio, confirm consent and the allowed purpose before supplying a recording to a service. A text transcript in this lab lets you practise evidence preservation without creating or uploading anyone's recording.

## 3. Studio and reconciliation

### Engineering route

1. Run the reference report and inspect each excluded or quarantined record.
2. Write an independent calculation using your preferred language or SQL. Use the source contract, not a copied result.
3. Add a conflicting duplicate, a malformed date, a refund with a positive amount, and an empty currency to a copy of the dataset.
4. Show how each input reaches an accepted, excluded, or review outcome. Never modify the original fixture.
5. Extract INV-014 into a schema with separate observed and calculated fields. Include evidence locations and review reasons.

### Business-owner route

1. Open the CSV in a spreadsheet and preserve a raw-data sheet. Import identifiers as text and dates using the supplied ISO format.
2. In a prepared table, mark duplicate, outside-period, missing-amount, and wrong-currency rows before calculating totals.
3. Calculate sales and refunds with separate formulas, then derive the net. Check the eight accepted events manually.
4. Ask the assistant for a report, then verify every numerical claim against the prepared table.
5. Create a meeting action list with task, owner, deadline, evidence timestamp, and unresolved questions.
